THE GAP

Where testing falls behind

  • Coverage drifts. Critical paths change with every release and the tests do not follow. Code assistants write tests when an engineer asks, and nobody asks for the ones that fell behind. Where traceability exists at all, it lives in a spreadsheet that is out of date by the next sprint.
  • The picture is split across tools. Test management, CI, observability and the issue tracker each hold part of it. Feedback arrives late and in pieces.
  • Triage is manual. Flaky tests and red builds are worked through by hand, one at a time. Recovery takes longer and releases slip.
HOW IT WORKS

From a change to an updated test suite

  1. 1Change: commit, pull request, spec, design or log signal
  2. 2Route: Policy Brain picks the model under your policies
  3. 3Generate and validate: tests for the changed behaviour, checked before review
  4. 4Test suites: placed at the lowest level that proves it
  5. 5Ledger: requirement to test to run to evidence
  1. A change lands. A commit, a pull request, a spec update, a design change or a new failure pattern in the logs you share with it.
  2. Policy Brain routes it. It picks the model for that kind of change, under your policies. It acts only on changes that can alter behaviour, so it is not writing tests for a rename.
  3. Agents generate and validate. The generator writes tests for the changed behaviour. A validator runs each test against the changed code; a judge checks that the written rationale matches the diff and your policy. Only tests that pass both reach a reviewer.
  4. The test suites update. New and changed tests land at the lowest level that can prove the behaviour, unit before API before UI, and are ranked by the risk of the path and the cost of the test.
  5. The ledger records it. Requirement to test to run to evidence, in a form your auditors can read.

It reports change failure rate, mean time to recovery, time to green, flaky reruns and test-suite acceptance, so you can see what it changed.

COMPONENTS

What is inside

Coverage Graph

Keeps a live map of which behaviours have tests and which do not. It is built from the code, the specs, the designs and the logs you share with it, so a path that is busy in production but thin in tests moves to the top of the list.

Policy Brain

The routing engine. For each change it looks at what changed and in which part of the system, then applies your policies for accuracy, latency, cost and data handling to pick a model from the ones you have approved. Each routing decision is recorded with the policy that drove it, so a reviewer can see why a given model handled a given change. A patent application for this engine has been filed in India.

Traceability Ledger

An append-only record that links each requirement to the tests that cover it, each test to the runs that executed it, and each run to its evidence. When someone asks why a release was safe to ship, the evidence is already assembled.

USE CASES

What it takes on

  • Test maintenance. Keeps tests current as the code under them changes, and hands the update to your team as a pull request.
  • Test generation for changed behaviour. New tests for what a change altered, opened as a pull request with the diff they cover.
  • Flaky-test triage. Identifies tests that fail without a code change, attaches the likely cause (timing, ordering, environment) and quarantines them, so a red build means a real failure.
  • Coverage re-prioritisation. Moves effort to the paths the Coverage Graph ranks highest.
  • Root-cause analysis on failed runs. A first diagnosis attached to the failure before an engineer opens it.
  • Release gates with evidence. The lineage and the results in one place when someone has to sign off.
SECURITY

Security and deployment

Your models

It runs on the LLM you already use. Nothing routes through a model you have not approved.

Your environment

Scoped integrations

Read access to GitHub or GitLab, Jira, your CI and the logs you share with it. Its only output into your repository is a pull request for your team to review. Secrets are masked.
